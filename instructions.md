# 🎮 AutoOffline — инструкция по установке и настройке

Привет! Это альтернативная инструкция для **AutoOffline** — плагина для автоматической выдачи кодов и работы с офлайн-аккаунтами через FunPay Cardinal.

Плагин позволяет автоматизировать выдачу:

* Steam Guard через SDA;
* Steam Guard через почту;
* Google Authenticator / TOTP;
* Denuvo-активаций.

Ниже разберём установку и основные настройки плагина.

---

# 📌 Что умеет AutoOffline

AutoOffline умеет:

* автоматически определять оплаченные заказы FunPay;
* выдавать коды только покупателям с подходящим активным заказом;
* создавать отдельные аккаунты для разных игр и товаров;
* привязывать FunPay LOT ID к конкретному аккаунту;
* создавать отдельную команду для каждого лота;
* устанавливать лимиты выдачи;
* работать с очередью Steam Guard и TOTP;
* получать Steam Guard-коды через SDA;
* получать Steam Guard-коды из почты;
* генерировать TOTP-коды;
* работать с Denuvo-слотами;
* включать и выключать аккаунты;
* отдельно включать и выключать лоты в плагине и на FunPay;
* менять сообщения выдачи;
* вести уведомления и аналитику;
* сохранять историю заказов и выдач;
* создавать зашифрованные резервные копии;
* восстанавливать базу;
* обновлять плагин из Telegram-интерфейса.

---

# 🚀 Установка

Для работы AutoOffline нужен установленный **FunPay Cardinal**.

После установки Cardinal:

1. скачайте актуальный файл AutoOffline;
2. откройте Telegram-бота Cardinal;
3. отправьте команду:

```text
/menu
```

4. перейдите в раздел **«Плагины»**;
5. загрузите файл AutoOffline;
6. после установки откройте плагин из списка.

Также панель AutoOffline можно открыть командами:

```text
/autooffline
```

или:

```text
/ao
```

# 🎮 Аккаунты

В AutoOffline сначала создаются **аккаунты**, а уже потом к ним привязываются FunPay-лоты.

Один аккаунт содержит:

* тип выдачи;
* данные для получения кода;
* название;
* лимиты;
* настройки очереди;
* собственный текст выдачи;
* статистику выданных кодов;
* при необходимости настройки Denuvo.

Поддерживаются три основных типа создаваемых аккаунтов.

---

# 🔐 Steam Guard (SDA)

Этот режим используется, если у вас есть `shared_secret` Steam Guard.

Добавить данные можно вручную или через `.maFile`.

Если загружается `.maFile`, плагин самостоятельно получает из него нужный `shared_secret`.

После добавления можно указать понятное название, например:

```text
Steam Main
```

Для Steam Guard можно включить очередь.

---

# 📧 Steam Guard через Email

Этот режим позволяет автоматически получать Steam Guard-код из электронной почты.

При добавлении нужно указать:

1. адрес электронной почты;
2. пароль почты или пароль приложения;
3. название аккаунта.

Плагин умеет автоматически работать через IMAP с поддерживаемыми почтовыми сервисами.

Если почтовый сервис напрямую не поддерживается через встроенный IMAP, можно использовать **SmakMail API**.

Плагин проверяет данные почты сразу при добавлении.

---

# 🔢 Google Authenticator / TOTP

Этот тип подходит для сервисов, использующих обычный TOTP.

Можно отправить:

* Base32 secret;
* ссылку вида `otpauth://`.

Плагин проверит secret и после этого сможет самостоятельно генерировать коды.

Например, аккаунт можно назвать:

```text
Ubisoft Main
```

Для TOTP также доступна очередь.

# ✏️ Настройки аккаунта

После создания аккаунта можно открыть его карточку.

В ней доступны:

* включение или выключение выдачи;
* изменение названия;
* замена `secret` или почты;
* настройка лимитов;
* настройка очереди;
* Denuvo;
* изменение текста выдачи;
* удаление аккаунта.

---

# 📛 Лимиты кодов

Для каждого аккаунта можно установить отдельные ограничения.

Есть два режима.

## 1️⃣ По количеству кодов

Вы указываете максимальное количество кодов, которое покупатель может получить с этого аккаунта.

Например:

```text
5
```

означает максимум 5 кодов.

Можно также отправить:

```text
-
```

чтобы убрать ограничение.

---

## ♻️ Сброс лимита

Если установлен лимит по количеству, можно настроить его автоматический сброс.

Например:

```text
30м
```

```text
2ч
```

```text
1д
```

То есть после указанного времени покупатель снова сможет получать коды.

Если отправить:

```text
-
```

лимит не будет автоматически сбрасываться.

---

## 2️⃣ По времени

В этом режиме количество кодов не ограничивается.

Вместо этого покупатель получает доступ на определённое время.

Например:

```text
30м
```

означает, что в течение 30 минут покупатель может получать коды без ограничения по количеству.

После окончания времени доступ закрывается.

Режимы **по количеству** и **по времени** взаимоисключающие.

---

# ⏳ Очередь Steam Guard

Если несколько покупателей почти одновременно запросят Steam Guard-код от одного аккаунта, выдавать всё сразу небезопасно.

При включённой очереди:

1. первый запрос обрабатывается сразу;
2. остальные становятся в очередь;
3. между выдачами с одного Steam-аккаунта выдерживается минимум **15 секунд**.

Это помогает избежать ситуации, когда несколько покупателей получают некорректные или конфликтующие коды.

---

# ⏳ Очередь TOTP

TOTP-код действует в пределах временного окна примерно **30 секунд**.

Если два покупателя одновременно запросят TOTP-код, нельзя отдавать им один и тот же код.

Поэтому при включённой очереди:

1. первый покупатель получает текущий код;
2. следующий покупатель ждёт;
3. ему выдаётся код из следующего TOTP-окна.

Таким образом один и тот же код не отправляется двум людям.

# 💬 Текст выдачи

Для каждого аккаунта можно создать собственный шаблон сообщения.

Если свой шаблон не указан, используется общий.

В тексте доступны переменные:

```text
{code}
{account}
{lot}
{order_id}
{buyer}
{left}
{total}
{quantity}
{slot_info}
```

Например:

```text
✅ Ваш код: {code}

Осталось выдач: {left}/{total}
```

Чтобы вернуться к общему шаблону, при редактировании можно отправить:

```text
-
```

# 🎮 Denuvo

Для Steam SDA-аккаунта можно дополнительно включить режим Denuvo.

При настройке указывается название игры.

Например:

```text
F1 25
```

Также можно задать количество одновременных Denuvo-активаций для конкретного аккаунта.

Например:

```text
5
```

Это означает, что аккаунт может одновременно использоваться максимум для пяти активных слотов.

---

# 🎮 Центр Denuvo

В отдельном разделе **Denuvo** отображается текущее состояние задач и слотов.

В меню доступны действия:

* **🔄 Обновить статус**
* **🔄 Синхронизировать слоты**
* **♻️ Повторить ошибки**
* **🧹 Очистить завершённые**

Если какая-то Denuvo-задача временно завершилась ошибкой, её можно повторить через соответствующую кнопку.

Завершённые задачи можно очищать из списка.

# 📮 SmakMail API

SmakMail используется для Steam Guard через Email в тех случаях, когда почтовый сервис нельзя нормально подключить напрямую через встроенный IMAP.

Чтобы установить ключ:

1. откройте **📮 SmakMail API**;
2. отправьте API key;
3. плагин сохранит его локально.

Чтобы удалить ключ, отправьте:

```text
-
```

Если обычный IMAP для вашей почты поддерживается, SmakMail может вообще не понадобиться.

# 🛒 Настройка лотов

FunPay-лоты создаются после аккаунтов.

Сам лот не хранит отдельный secret или отдельные лимиты.

Он связывает:

* FunPay LOT ID;
* название товара;
* тип аккаунта;
* конкретный аккаунт;
* команду покупателя.

Лимиты, очередь, сообщение и настройки Denuvo берутся из привязанного аккаунта.

---

# ➕ Добавление лота

При добавлении нового лота нужно пройти несколько шагов.

## Шаг 1. LOT ID

Отправьте числовой FunPay LOT ID.

Например:

```text
12345678
```

Один LOT ID нельзя добавить дважды.

---

## Шаг 2. Название

Укажите понятное название товара или игры.

Например:

```text
Steam Offline — F1 25
```

---

## Шаг 3. Тип аккаунта

Выберите тип аккаунта:

* Steam Guard (SDA);
* Steam Guard (Email);
* Google Authenticator / TOTP.

Плагин показывает только те типы, для которых у вас уже есть подходящие аккаунты.

---

## Шаг 4. Аккаунт

Выберите конкретный аккаунт, который будет использоваться для этого лота.

Один лот привязывается к одному совместимому аккаунту.

---

## Шаг 5. Команда

Укажите команду, которую покупатель должен написать в чате FunPay.

Например:

```text
!code_f1
```

Команда должна быть уникальной.

Нельзя использовать одну и ту же команду для двух разных лотов.

---

# 💬 Как происходит выдача

Обычный сценарий выглядит так:

1. покупатель оплачивает FunPay-заказ;
2. AutoOffline записывает заказ в базу;
3. покупатель пишет команду, указанную в настройках лота;
4. плагин находит лот по этой команде;
5. проверяет, что лот включён;
6. ищет подходящий оплаченный заказ этого покупателя;
7. проверяет лимиты;
8. проверяет доступность привязанного аккаунта;
9. получает или генерирует код;
10. отправляет сообщение покупателю;
11. записывает выдачу в статистику и usage.

То есть просто написать команду без подходящего оплаченного заказа недостаточно.

---

# 🛡 Защита от выдачи без заказа

Перед выдачей AutoOffline ищет подходящий активный заказ.

Если заказ не найден, код не выдаётся.

Плагин также отслеживает системные сообщения FunPay об оплате и возврате заказа.

Если заказ был возвращён, покупателю блокируется получение новых кодов по этому заказу.

# 🟢 Состояние лотов

У лота есть два независимых состояния.

## Лот в плагине

Определяет, будет ли AutoOffline обрабатывать его команды.

Если лот выключен в плагине, автоматическая выдача по нему не работает.

## Лот на FunPay

Определяет состояние самого предложения на площадке FunPay.

Поэтому возможна ситуация:

* лот включён в AutoOffline;
* но выключен на FunPay;

или наоборот.

Оба состояния переключаются отдельно.

# 📤 Бэкап

Все основные данные AutoOffline хранятся локально.

Через меню обслуживания можно скачать зашифрованный бэкап.

В нём сохраняются:

* аккаунты;
* лоты;
* заказы;
* настройки;
* usage;
* история;
* другие данные плагина.

Бэкап можно использовать для переноса или восстановления конфигурации.

---

# 📥 Импорт бэкапа

Для восстановления отправьте ранее созданный файл через кнопку **«Импортировать бэкап»**.

Перед импортом плагин проверяет структуру файла.

Если файл не является корректным бэкапом AutoOffline, он не будет установлен.

---

# 🩺 Проверить базу

Функция проверяет локальную базу AutoOffline.

Если основной файл повреждён, плагин может попытаться восстановить его из резервной копии.

После проверки отображается информация о состоянии базы и количестве найденных:

* аккаунтов;
* лотов;
* заказов.

---

# ♻️ Сбросить usage

Usage содержит информацию о том, сколько кодов уже получил каждый покупатель.

Кнопка **«Сбросить usage»** сбрасывает эту статистику.

После этого лимиты покупателей начинают считаться заново.

При этом:

* заказы не удаляются;
* логи не удаляются.

---

# 🔐 Хранение данных

Все основные данные AutoOffline хранятся **локально**.

База хранится в зашифрованном JSON.

Для шифрования используется локальный ключ, который находится отдельно от самой базы.

В базе могут находиться чувствительные данные, поэтому:

> **Не отправляйте базу, резервные копии и локальный ключ посторонним людям.**

Для обычного переноса используйте встроенные функции **бэкапа и импорта**.

---

# ♻️ Обновление плагина

AutoOffline поддерживает обновление из собственного меню.

Есть два варианта.

## 📥 Обновить локально

Вы отправляете новый `.py`-файл AutoOffline.

Перед установкой файл проверяется.

Текущий файл сохраняется в резервную копию, а база и настройки остаются на месте.

## 🌐 Обновить онлайн

Плагин может проверить обновление через настроенный источник и предложить установить новый файл.

---

# 🗑 Удаление

Из главного меню можно удалить файл плагина.

Удаление самого `.py`-файла и удаление локальной базы — разные вещи.

Если данные вам могут понадобиться позже, перед удалением обязательно сделайте бэкап.

---

# ❓ Если код не выдаётся

Проверьте по порядку:

1. включён ли AutoOffline;
2. включён ли нужный аккаунт;
3. включён ли нужный лот;
4. правильно ли указан FunPay LOT ID;
5. правильная ли команда настроена для лота;
6. существует ли оплаченный заказ покупателя;
7. не закончился ли лимит;
8. правильно ли настроен `secret` или почта;
9. включена ли очередь и не находится ли запрос в ожидании;
10. нет ли ошибки в логах;
11. если используется Denuvo — есть ли свободный слот.

# ✅ Рекомендуемая первоначальная настройка

Если настраиваете AutoOffline впервые, сделайте так:

1. добавьте один аккаунт;
2. проверьте правильность secret или почты;
3. установите небольшой тестовый лимит;
4. включите очередь для Steam Guard или TOTP;
5. создайте один FunPay-лот;
6. привяжите его к аккаунту;
7. создайте уникальную команду;
8. проверьте состояние лота;
9. сделайте тестовый заказ;
10. убедитесь, что команда выдаёт код только после оплаты.

После этого можно добавлять остальные аккаунты и лоты.

# ✅ Готово

После добавления аккаунта, настройки лимитов и привязки FunPay-лота AutoOffline готов к автоматической выдаче.

Главное — внимательно настраивайте:

* правильный LOT ID;
* правильный тип аккаунта;
* лимиты;
* очередь;
* команду;
* состояние аккаунта и лота.

Если возникают проблемы, первым делом смотрите **логи**, **аналитику** и **состояние** плагина.
